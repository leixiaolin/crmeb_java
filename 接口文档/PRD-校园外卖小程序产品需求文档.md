# 校园外卖小程序 产品需求文档（PRD）

> **文档版本**: v1.0
> **创建日期**: 2026-05-20
> **产品名称**: 校园外卖小程序
> **平台**: 微信小程序（仅微信小程序，不含 H5、App、支付宝小程序）
> **基线系统**: 基于 CRMEB Java 商城系统二次开发

---

## 一、项目概述

### 1.1 产品定位

校园外卖配送平台，面向校外商家，为校内学生提供外卖点餐与配送服务。平台统一管理商家、商品、订单、骑手配送，支持多学校、多区域运营。

### 1.2 核心价值

- **学生端**: 便捷点餐，配送到宿舍楼下
- **商家端**: 线上接单，拓展校园市场
- **平台端**: 统一运营管理，抽佣盈利

### 1.3 系统角色

| 角色 | 说明 |
|------|------|
| 用户（学生） | 微信小程序下单，手机号认证 |
| 商家 | 嵌入管理后台操作，接单/商品管理/退款 |
| 平台管理员 | 后台管理系统全局管理 |
| 运营 | 后台运营配置、活动管理 |
| 总客服 | 处理用户投诉、工单 |
| 财务 | 商家结算、账单、提现审核 |
| 骑手 | 首期由后台端更新配送状态，二期独立骑手端 |

### 1.4 交付范围

首期 MVP 需同时交付：
- ✅ 用户端微信小程序
- ✅ 商家端（嵌入管理后台）
- ✅ 运营后台管理系统
- ⏳ 骑手端（二期规划，首期由后台更新配送状态）

| 功能 | 描述 |
|------|------|
| 收货地址选择 | 选择已保存的地址（学校、楼栋、宿舍号） |
| 商品清单 | 展示已选商品明细 |

**配送费规则**:
- **梯度制收费**: 按宿舍楼自定义梯度，最高楼层到最低楼层收费均匀递减，按宿舍楼单独配置
- **雨天附加费**: 后台人工开关控制，下雨时开启附加费，未下雨时人工手动一键退还
- **起送价/配送费**: 由平台统一配置

### 2.6 订单模块

**订单状态流转**:

```
待付款 → 待接单 → 配送中 → 已送达 → 已完成
                ↓
               已取消（付款前/接单前）
```

| 状态 | 说明 |
|------|------|
| 待付款 | 用户下单未支付 |
| 待接单 | 已付款等待商家接单 |
| 已取消 | 付款前或商家接单前可取消 |
| 配送中 | 商家接单后进入配送（首期后台更新状态） |
| 已送达 | 骑手送达（后台确认） |
| 已完成 | 用户确认或自动完成 |
| 退款中 | 用户申请退款 / 商家退款处理中 |

**订单跟踪**:
- 商家接单 → 骑手取餐 → 配送中 → 送达（首期由后台端更新状态）

**订单操作**:
- 再来一单
- 申请退款
- 联系商家
- 联系骑手

**预约配送**: 支持按日期 + 时间段预约

**智能排序**: 后台订单按宿舍号智能排序，排序规则为：楼栋 → 楼层 → 宿舍号

## 五、配送模块

### 5.1 配送模式

| 阶段 | 模式 | 说明 |
|------|------|------|
| 首期 | 平台自配送 | 平台自有骑手配送，后台更新配送状态 |
| 二期 | 第三方对接 | 可对接第三方配送平台（预留接口） |

### 5.2 骑手管理

- 首期：无独立骑手端，后台端手动更新配送状态
- 二期：开发独立骑手端小程序

### 5.3 配送费规则

**梯度制收费（按宿舍楼自定义配置）**:

```
示例：
  6楼: 配送费 3.0 元
  5楼: 配送费 2.5 元
  4楼: 配送费 2.0 元
  3楼: 配送费 1.5 元
  2楼: 配送费 1.0 元
  1楼: 配送费 0.5 元

每栋宿舍楼可单独配置梯度规则
最高楼到最低楼收费均匀递减
```

**雨天附加费**:
- 后台人工开关控制
- 下雨时开启附加费
- 未下雨时人工手动一键退还

### 5.4 起送价

- 由平台统一配置，非商家配置
