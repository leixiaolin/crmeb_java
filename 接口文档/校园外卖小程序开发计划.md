# 校园外卖小程序 MVP 开发计划

## Summary

- 基于现有 CRMEB Java 二开，首期交付微信小程序用户端、嵌入现有 `admin/` 的平台运营后台和商家后台能力。
- 不开发独立骑手端、H5、App、支付宝小程序；首期配送状态由后台人工更新。
- 复用现有用户、商品、订单、优惠券、微信支付、上传、权限、统计基础能力；新增“校园外卖”业务域，避免大面积改造原商城链路。

## 开发前技术方案

- 开发前必须先评审《校园外卖小程序技术方案设计.md》。
- 重点确认四个高风险问题：订单状态机、商家数据隔离、校园地址模型、配送费规则。
- 技术方案未评审通过前，不进入订单、支付、退款、配送相关开发。

## Key Changes

- 后端新增校园外卖域：学校/校区、宿舍楼、楼层配送费、雨天附加费、商家入驻与资质、商家商品审核、外卖订单扩展、配送状态日志、商家结算/提现、周卡/月卡。
- 订单模型采用“现有 `StoreOrder` + 外卖扩展表”方案：保留原订单支付、退款、优惠券、日志能力；外卖扩展表存商家、学校、宿舍、楼层、预约时间、配送费、雨天费、配送状态、智能排序字段。
- 订单状态按首期固定流转：待付款 -> 待接单 -> 配送中 -> 已送达 -> 已完成；取消和退款按 PRD 规则处理，接单前可取消，接单后用户不可取消。
- 管理后台新增“校园外卖”菜单：商家管理、商品审核、外卖订单、配送配置、雨天附加费开关、优惠活动、商家结算、数据统计。
- 商家后台嵌入现有 admin：商家账号只允许管理自己店铺的订单、商品、评价、退款、统计；权限通过现有角色/菜单/数据范围扩展。
- 小程序改造为四个核心入口：首页、外卖/美食、订单、我的；地址管理改为学校、楼栋、宿舍号、楼层结构；结算页增加预约配送、餐具、备注、配送费明细。

## Public Interfaces

- 用户端新增/扩展接口：
  - 学校与宿舍地址：学校列表、楼栋列表、地址增删改查、默认地址。
  - 商家与商品：商家列表、筛选排序、商家详情、商品分类、商品规格、收藏、评价。
  - 结算与订单：价格试算、创建外卖订单、微信支付、取消订单、确认送达、退款申请、再来一单。
  - 会员卡：周卡/月卡列表、购买、权益状态。
- 管理端新增接口：
  - 商家入驻审核、资质审核、上下线、商家账号绑定。
  - 商品审核、商家商品上下架、每日库存维护。
  - 外卖订单接单/拒单、配送状态更新、智能排序、退款处理。
  - 配送规则配置：起送价、楼层梯度费、雨天附加费、一键开启/关闭。
  - 商家账单、平台抽佣、提现申请、财务审核。
- 小票打印、短信、订阅消息、微信支付证书等外部服务接口先做配置与适配层；真实商户号、短信账号、打印机配置未准备时使用可关闭开关和失败日志。

## Milestones

1. 基础数据与权限
   - 建表、初始化菜单权限、商家角色、学校/楼栋/楼层配送费配置。
   - 完成上传资质、商家审核、商家后台数据隔离。

2. 商品与商家
   - 商家商品创建、规格、库存、上下架、平台审核。
   - 用户端商家列表、搜索、筛选、商家详情、购物车。

3. 下单与支付
   - 地址选择、配送费计算、优惠互斥计算、预约配送、订单创建、微信支付。
   - 接单前取消、商家拒单自动退款、部分退款基础链路。

4. 订单履约
   - 商家接单/拒单、后台配送状态更新、订单详情轨迹、智能排序。
   - 小程序订单列表、状态跟踪、确认完成、评价。

5. 运营与财务
   - 优惠券、新人优惠、满减、秒杀入口适配校园商家。
   - 商家账单、抽佣、提现审核、销售统计、订单导出。

6. 联调上线
   - 微信小程序账号、支付商户号、SSL、域名、短信、飞鹅打印配置齐备后做全链路联调。
   - 灰度一个学校/校区，验证稳定后再开放多校区。

## Test Plan

- 后端：Maven package；核心服务补单元测试，覆盖配送费计算、订单状态流转、取消退款、商家数据隔离、智能排序。
- 管理后台：`npm run lint`，重点手工验证菜单权限、商家只能看自有数据、订单操作按钮状态正确。
- 小程序：微信开发者工具验证首页、商家详情、结算、支付、订单详情、退款、地址管理。
- 端到端场景：
  - 新用户领券下单并支付，商家接单，后台标记送达，用户确认完成。
  - 接单前用户取消，自动退款并回滚优惠券/库存。
  - 商家拒单，自动原路退款。
  - 雨天附加费开启/关闭后，结算金额正确变化。
  - 不同商家维度的新老用户判断正确。

## Assumptions

- 首期只做微信小程序，现有 `app/` uni-app 作为承载端，但只保证微信小程序运行。
- 首期使用服务器本地存储图片，不引入云存储。
- 首期优惠不叠加，按互斥规则选择一种最优优惠。
- 首期营业时间使用单一固定时段，多营业时段放二期。
- 首期骑手无独立端，配送状态由后台人工维护。
- 现有商城通用订单能力继续保留，校园外卖通过扩展表和新菜单隔离实现。
